# SyncBase

SyncBase — консольный инструмент для безопасной двусторонней синхронизации
локального вольта с папкой приложения на Яндекс.Диске.

Вольт — папка с файлом `.syncbase`. Всё её содержимое напрямую зеркалируется в
`app:/`; уровней «категория → проект» больше нет. Для разделения данных создайте
несколько вольтов с отдельными OAuth-приложениями и токенами.

## Установка

```bash
pip install syncbase
```

Для разработки:

```bash
pip install -e .
```

Из исходного каталога также работает совместимый launcher:

```bash
python sync_base.py list
```

## Настройка Яндекс.Диска

1. Зарегистрируйте приложение на [Яндекс.OAuth](https://oauth.yandex.ru/).
2. Выдайте приложению право `cloud_api:disk.app_folder`.
3. Получите OAuth-токен.
4. Создайте локальную папку вольта и файл `.syncbase`:

```bash
cd /путь/до/вольта
echo 'YANDEX_DISK_TOKEN=y0__xCPz...' > .syncbase
```

Файл `.syncbase` содержит секрет. Не добавляйте его в Git. SyncBase всегда
исключает `.syncbase` и `.sync_cache` из синхронизации независимо от правил
`.syncignore`.

Каждый токен с доступом `cloud_api:disk.app_folder` видит только папку своего
OAuth-приложения. Перед первым сохранением проверьте корень командой
`syncbase list`.

## Команды

```bash
# Показать верхний уровень локального и облачного корней
syncbase list

# Показать локальные изменения относительно последнего save
syncbase status all

# Зеркалировать весь локальный вольт в app:/
syncbase save all

# Зеркалировать весь app:/ в локальный вольт
syncbase load all
```

Команды можно запускать из корня вольта или любой вложенной папки: SyncBase
ищет ближайший `.syncbase`, поднимаясь вверх по дереву каталогов.

Старые проектные формы не поддерживаются. В частности, `all all`,
`<category> <project>` и вызов `save`/`load` без аргумента `all` завершаются
ошибкой использования.

## Защита от потери данных

SyncBase блокирует операцию, если она:

- перезапишет более новый файл более старым;
- удалит файл, существующий только на целевой стороне.

Для осознанной принудительной синхронизации добавьте `-f` или `--force`:

```bash
syncbase save all --force
syncbase load all --force
```

## `.syncignore`

Один файл `<vault>/.syncignore` задаёт правила для всего вольта. Поддерживаются
шаблоны `*`, `?`, исключения `!` и комментарии `#`.

```gitignore
.git/
__pycache__/
*.log
node_modules/
!important.log
```

Если `.syncignore` отсутствует, SyncBase создаст его при первом сканировании.
Сам `.syncignore` синхронизируется между копиями вольта.

## Структура вольта

```text
MyVault/
├── .syncbase       # локальный OAuth-токен, никогда не синхронизируется
├── .syncignore     # правила всего вольта
├── .sync_cache     # локальный кэш status, никогда не синхронизируется
├── docs/
├── src/
└── любые другие файлы и папки
```

Облачный корень `app:/` зеркалирует содержимое `MyVault/` без дополнительного
уровня каталога.

## Python API

```python
from syncbase import SyncVault, find_vault

vault_path, token = find_vault() or (None, None)
if vault_path and token:
    SyncVault(vault_path, token).sync_save()
```

HTTP-клиент доступен как `syncbase.client.YandexDiskClient`. Исторический импорт
`yandex_disk_client.YandexDiskClient` сохранён как тонкий адаптер.
