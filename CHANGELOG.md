# Changelog

## 0.2.4 — 2026-09-08

- Расширен встроенный шаблон `.syncignore`: окружения и кэши Python,
  зависимости и кэши JS-сборщиков, каталоги VCS, настройки IDE и служебные файлы.
  При первом сканировании он копируется в проекты без `.syncignore`;
  существующие файлы правил не меняются.
- Правила с простым именем действуют во вложенных каталогах; точные правила
  с начальным `/` остаются привязанными к корню проекта.

## 0.2.3 — 2026-09-08

- Удалён исторический импорт `yandex_disk_client` из исходников и упаковки.
  Используйте `from syncbase.client import YandexDiskClient`.

## 0.2.2 — 2026-09-08

- Добавлен инкрементальный индекс MD5 в `.sync_cache` версии 3.0: неизменившиеся
  файлы проверяются по размеру, наносекундным mtime/ctime и идентификатору файла
  без чтения содержимого. Кэш 2.0 обновляется автоматически после полного прохода.
- Ускорен локальный обход через `os.scandir`; увеличен блок чтения MD5 до 1 МиБ.
  Повторное сканирование после `load` использует уже вычисленные хеши.
- `status` сохраняет актуальный индекс отдельно от снимка последнего save/load;
  повторная проверка не скрывает несинхронизированные изменения.
- Кэш записывается компактным JSON с атомарной заменой. Служебные временные
  `.sync_cache.*.tmp` исключены из локальной и облачной синхронизации.
- Облачное дерево сканируется одним пулом с ограниченным числом задач без
  ожидания завершения целого уровня каталогов. Ошибки получения списка, включая
  последующие страницы, останавливают синхронизацию вместо использования неполного дерева.
- Добавлены регрессионные тесты и воспроизводимый локальный бенчмарк индексации.

## 0.2.1 — 2026-09-08

- Исправлена модель одноуровневого вольта: `<vault>/<project>/` соответствует
  `app:/<project>/`; удалён только уровень категорий.
- Возвращены контекстные `syncbase status`, `syncbase save` и `syncbase load`
  из папки проекта или любой её подпапки.
- Массовые команды с `all` и явный одноуровневый селектор проекта работают
  через `SyncVault`; синхронизация проекта вынесена в `SyncProject`.
- Остаточные облачные `*.tmp` от прерванных загрузок больше не блокируют `save`
  и удаляются без `--force`; клиент также пытается удалить их сразу после сбоя.
- Добавленные и удалённые файлы с одинаковыми MD5 и размером распознаются как
  переименование: `save` использует облачный move, `load` — локальный move.

## 0.2.0 — 2026-09-06

- Хранилище преобразовано в одноуровневый вольт: локальный корень напрямую
  зеркалируется в `app:/`.
- Основным API стал `SyncVault`; удалены `SyncBase`, `SyncProject` и обход
  категорий/проектов.
- CLI принимает `status all`, `save all` и `load all`; старые project-селекторы
  и форма `all all` больше не поддерживаются.
- `.syncbase` и `.sync_cache` гарантированно исключены из синхронизации.
- Тесты и документация обновлены под модель вольта.

## 0.1.3 — 2026-08-07

- Возвращён совместимый импорт `yandex_disk_client` поверх встроенного клиента.
- Исторический `python sync_base.py ...` переведён на новую пакетную CLI.
- Исправлена загрузка небольших файлов: upload URL получает сырой поток байтов,
  а не `multipart/form-data`.
- Добавлены повторные попытки загрузки при 429, 5xx и сетевых ошибках.
- Обновлены сетево-независимые тесты клиента и документация структуры.
